    Class CashFlowCardComponent

    The cash-flow tab's body below the search row: the totals strip beside the view toggle, then the monthly timeline or the per-product table behind it.

    Remarks

    Presentational. The totals, the chart option and the rows are all computed by the page, and the three controls are announced rather than acted on: the view switch, the filter term the export also reads, and the download, which needs the CSV service.

    No sort. This table is the one report table with no sortable columns - the per-product breakdown is read against the timeline above it rather than reordered - so there is no sortChange here.

    hasRows gates both the heading and the empty state, and it asks whether the per-product query has answered with anything. That query is lazy: the chart half never needs it, so the page fetches it on the first switch to the table. Until then this renders the empty state, which is the honest reading of a table whose rows have not been asked for yet.
