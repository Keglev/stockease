    Function buildRecordMovementRequest

    • buildRecordMovementRequest(
          draft: MovementDraft,
      ): {
          productId: number;
          quantity: number;
          reason: "LOST" | "DESTROYED";
          remark: "EXPIRED" | "IN_TRANSIT_TO_CUSTOMER" | "INTERNAL" | "FROM_SUPPLIER";
      }

      Builds the record payload from a form draft.

      Three keys, always the same three: every reason this endpoint accepts is a loss, so the remark is unconditional, and no reason carries a price - a cost snapshot belongs to a purchase line.

      Parameters

      • draft: MovementDraft

      Returns {
          productId: number;
          quantity: number;
          reason: "LOST" | "DESTROYED";
          remark: "EXPIRED" | "IN_TRANSIT_TO_CUSTOMER" | "INTERNAL" | "FROM_SUPPLIER";
      }

      • productId: number

        Format: int64

        Description

        Required; message: "Product is required."

        Example

        3
      • quantity: number

        Description

        Must be positive; message: "Quantity must be positive."

        Example

        2
      • reason: "LOST" | "DESTROYED"

        Description

        Required, and must be LOST or DESTROYED. This endpoint is a loss ledger: stock never enters through it, so no incoming reason is accepted here.

      • remark: "EXPIRED" | "IN_TRANSIT_TO_CUSTOMER" | "INTERNAL" | "FROM_SUPPLIER"

        Description

        Required: every reason this endpoint accepts is a loss, and a loss must say what happened to the stock. A database CHECK enforces the same rule as a backstop.

        Example

        EXPIRED
